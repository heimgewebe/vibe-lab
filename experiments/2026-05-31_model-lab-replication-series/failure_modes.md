# Model-Lab Replication-Series — Failure Modes

## When does this approach fail or mislead?

### Experimental design

- **Cosmetic relabeling or undeclared multi-axis drift.** A useful comparison needs one predeclared intervention and fixed challenge, acceptance, evaluation, verification, runtime, evidence, and human-intervention surfaces.
- **Historical runs rewritten into a cleaner control.** Run-001, Run-002, and Run-003 remain historical context.
- **Assigned instructions mistaken for observed compliance.** Compliance, contamination, ordering, and intervention evidence belong to a later execution.
- **A frozen design mistaken for execution permission.** A valid design does not bind runtime values, authorize execution, record measurements, permit assessment, close `weak_condition_contrast`, or make the series comparison-ready.

### Prompt scope

- **The complete intervention is interpreted as one isolated sentence.** The treatment-only bundle includes the specification requirement, ordering and completeness rules, format and constraint examples, prompt length, internal structure, directive strength, motivational framing, and required sections.
- **A later observation is assigned to one component.** Attribution is limited to the complete bundle, not to one sentence, the canonical Spec-First wording, examples, length, structure, rhetoric, or required sections alone.
- **False prompt constants are declared.** Only language, permissions, composition order, benchmark, and shared condition are constant across arms.
- **Control becomes a second intervention.** Control is the neutral absence of the added positive workflow requirement, not an opposing instruction.
- **Experiment metadata leaks into delivery.** Roles, axis names, hypotheses, and comparison framing remain outside the shared condition and overlays.
- **Operative text drifts from its structured source.** Shared condition and overlays must remain deterministic, byte-checked renderings.

### Historical provenance and freeze

- **Internal hashes are mistaken for source provenance.** During every validation, the validator reads the historical Git object at each declared `source_commit_sha:source_path` and requires byte equality with the frozen snapshot.
- **Unavailable history is treated as success.** A missing commit, incomplete checkout, unavailable Git object, missing historical path, or byte mismatch fails closed. Full Git history is part of the CI verification surface.
- **Correct bytes are assigned to the wrong role.** Canonical source path, source commit, and expected `artifact_type` remain independently bound.
- **A reduced list replaces the full frozen gate.** Required dimensions and confounders are derived from the frozen full gate.
- **A directory is called a closed bundle while unknown files remain.** The actual file set must equal the contract-derived set, reject aliases and symbolic links, and match manifest coverage except for the manifest itself.
- **Hash validity is mistaken for semantic validity.** SHA-256 consistency does not establish methodological honesty, execution, compliance, or a condition effect.

### Delivery and measurement

- **Prompt bytes are not normalized.** Delivered files must be valid UTF-8, LF-only, and final-newline terminated.
- **A treatment specification is scored as an outcome.** It is part of the assigned process, not evidence of better output.
- **Abort time is recorded as validated-change time.** Before the shared verification surface passes, `time_to_validated_change_seconds` remains null.
- **Missing evidence is interpreted as absence of a problem.** Missing provenance, compliance, contamination, verification, or measurement evidence blocks later interpretation.

A contract can establish that a boundary was declared and mechanically preserved. It cannot establish that the experiment ran or that a causal or quality claim is warranted.
