# CONTEXT.md — Operator Learning Capture Sample

## Ausgangslage

Vibe-Lab soll produktiver in das heimgewebe-Oekosystem eingebunden werden. Die erste Idee, mehr Exportziele zu bauen, wurde verworfen: Sie wuerde erneut Output-Flaechen erzeugen, bevor geklaert ist, ob Vibe-Lab genuegend brauchbaren Input aus echter Arbeit bekommt.

Dieses Experiment prueft daher zuerst eine kleine Lernprobe aus vorhandenen Artefakten.

## Fokus

Die Probe fragt:

> Kann Vibe-Lab aus bereits vorhandenen PR-, Review-, CI- und Registry-Artefakten wiederkehrende Operator-Reibung erkennen, ohne sofort Grabowski, Bureau oder Leitstand umzubauen?

## Primaere Organe

- **Vibe-Lab:** Experiment- und Evidence-Flaeche.
- **Grabowski:** Quelle realer Operator-Arbeit und potentieller spaeterer Receipt-Erzeuger.
- **Bureau:** moegliches spaeteres Output-Ziel fuer Task-Kandidaten.
- **GitHub/CI:** Primaere Wahrheit fuer PR-, Review-, Merge- und Validierungsstatus.
- **RepoBrief/Lenskit:** spaetere Quelle fuer zitierbare Repo-Kontextbindung; in dieser Probe noch nicht direkt integriert.

## Begrenzung

Diese Probe baut keine Automatisierung.

Sie erzeugt:

- eine Rollenabgrenzung fuer produktive Vibe-Lab-Nutzung;
- eine kleine Sample-Datei;
- eine Assessment-Datei;
- Evidenz-JSONL fuer den ausgefuehrten Probe-Slice.

Sie erzeugt nicht:

- einen neuen Capture-Validator;
- Grabowski-Code;
- Bureau-Import;
- Leitstand-Signale;
- neue Export-Zielsysteme.
