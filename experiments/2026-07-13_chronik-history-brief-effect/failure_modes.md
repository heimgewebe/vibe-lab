# Failure modes

- Too few prior events make the treatment empty.
- Repository drift makes old outcomes irrelevant.
- Task classes or risk bands differ across conditions.
- Explicit operator-supplied assignments introduce selection imbalance; registration v2 establishes no fairness claim.
- An automatic assignment rule is added after registration and silently changes the design.
- A completed, planned or outcome-known case is relabeled as prospective admission.
- A repeated call changes an existing assignment or binds one evidence receipt to multiple case IDs.
- The reviewer can infer the condition and blinding fails.
- The same operator learns between cases, confounding the effect.
- History encourages an unchanged retry without live verification.
- Capture effort exceeds any saved diagnostic work.
- Rare harmful cases remain invisible in a six-case minimum.

The experiment does not establish general coding productivity, model-independent benefit, current repository state, safe retry, or authority to change Grabowski automatically.
