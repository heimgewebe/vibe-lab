# Context

A live read-only audit on 23 July 2026 found that the Grabowski task store is large enough to justify a learning-readiness check but is not itself a trustworthy supervised-routing dataset.

The frozen control artifact contains 15,852 task rows. Direct `acceptance_json` payloads were non-empty for 0 tasks. `chronik_context_json` existed for 6,167 tasks, and lifecycle receipt hashes existed for 9,309 tasks, but no direct reviewed semantic-outcome column was observed. The task table exposes no direct canonical route-identity column. Separately, the Agent Workspace audit found 46 manifests, 33 with `route_evidence`, and 27 with verified complete route evidence (58.7% of manifests). Of those verified route manifests, 14 have at least one task reference matching the current task store (51.85% of verified route manifests). This is partial cross-source joinability, not a complete route-plus-outcome training table: semantic outcomes remain absent and verified route coverage is incomplete.

Route identity is not absent, but it is split across authorities. Verified Agent Workspace `route_evidence` exists, and some workspace task references match task-store rows, but this join is only partial and still has no independently reviewed semantic outcome on the other side. The task argv surface contains coding-agent harnesses and explicit model arguments in several CLI forms, but argv inference remains diagnostic implementation detail rather than canonical routing-decision evidence and therefore does not satisfy the treatment label contract.

The exact aggregate baseline is generated by `tools/audit_task_store.py` into `artifacts/control-readiness.json` from the read-only task store and read-only Agent Workspace manifests. The artifact contains counts and schema-level coverage only; it does not export raw argv, prompts, transcripts, workspace ids, recommendation ids or private task content.

## Current decision boundary

- Do not train a routing model from terminal task states.
- Do not revive Heimlern as an active runtime.
- Use Vibe-Lab only for the registered experiment and reviewed proposal evidence.
- Keep Chronik as historical evidence, Grabowski as execution authority and Bureau as task/decision authority.
- Consider scikit-learn/Optuna only after the shadow-label readiness gate passes.
