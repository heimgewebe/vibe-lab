# Context

A live read-only audit on 23 July 2026 found that the Grabowski task store is large enough to justify a learning-readiness check but is not itself a trustworthy supervised-routing dataset.

The frozen control artifact contains 15,795 tasks. Direct `acceptance_json` payloads were non-empty for 0 tasks. `chronik_context_json` existed for 6,160 tasks and exposed aggregate keys such as operation, subject scope and task class, but no direct reviewed semantic-outcome key was observed. Lifecycle terminalization and lifecycle receipt hashes existed for 9,252 tasks. Only 405 tasks carried an explicit `--model` argument, and the task schema exposed no direct canonical route-identity column. These are valuable execution facts, but they do not prove whether the chosen coding route produced a correct, mergeable or decision-improving result.

Route identity is also incomplete as a direct training feature. The task argv surface contains coding-agent harnesses and some explicit `--model` arguments, but argv inference is implementation detail rather than canonical routing-decision evidence and therefore does not satisfy the treatment label contract.

The exact aggregate baseline is generated by `tools/audit_task_store.py` into `artifacts/control-readiness.json`. The artifact contains counts and schema-level coverage only; it does not export raw argv, prompts, transcripts or private task content.

## Current decision boundary

- Do not train a routing model from terminal task states.
- Do not revive Heimlern as an active runtime.
- Use Vibe-Lab only for the registered experiment and reviewed proposal evidence.
- Keep Chronik as historical evidence, Grabowski as execution authority and Bureau as task/decision authority.
- Consider scikit-learn/Optuna only after the shadow-label readiness gate passes.
