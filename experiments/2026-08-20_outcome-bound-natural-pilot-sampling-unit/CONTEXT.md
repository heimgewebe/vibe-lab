# Outcome-Bound natural pilot — sampling unit

Every Outcome-Bound successor so far has argued about *which* candidate belongs in a sample. None
of them froze *what one sample element is*. S1 made that gap visible: "an event arrived", "a
candidate identity came into existence" and "an existing candidate was superseded" were used as if
they were the same observation, so the same journal could be read as one arrival, three arrivals or
none depending on when the observer looked.

This revision closes exactly that seam and nothing else. It defines the sampling unit as
`candidate_identity_birth`, anchored on the canonical `identity_first_event` that itself carries
`operator_intake`, and it freezes the inclusion, exclusion, ordering, birth-proof and stop rules
around that anchor.

It is paper- and adversarial-only. It takes zero natural cases, consumes no Bureau candidate, sets
no activation boundary and no slot count, and grants no productive authority. A later pilot needs a
separate decision and a separate revision.

Inputs are terminal and unchanged: S0-R3 fixes C/S/B/E/T/Q admission semantics; S1-R2 fixes
canonical candidate identity, sequence-before-naturalness and natural-source independence. The
predecessor task OPERATOR-INTEGRATION-LOOP-V1-T033 result `REJECT_THIS_REVISION` on
heimgewebe/vibe-lab#347 (merge `5da2773bd3398aea66d7fe1175a67d9b9e174178`) is the reason a separate
sampling-unit revision exists at all.

Authority stays external to Vibe-Lab: Bureau owns candidate and event truth, Grabowski owns
execution receipts, Git/GitHub/CI own revision truth. This experiment stores references, a frozen
rule and frozen paper cases only.
